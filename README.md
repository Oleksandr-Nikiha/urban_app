# Urban Mini App

**Telegram Mini App для замовлення їжі** з двох закладів у Вишгороді — Urban Pizza & Sushi та Urban Bakery & Coffee.
Каталог, кошик і профіль живуть у веб-застосунку всередині Telegram; бот лишається точкою входу
та каналом нотифікацій.

> **Статус: Фази 1–3, 5–7 реалізовані: проведено рефакторинг API та сервісного шару (Clean/Layered Architecture), оптимізацію бази даних та міграцій (чистка дублікатів індексів, видалення мертвого поля products.image, додавання цільових FK/композитних індексів, міграція 0026), додано POS-портал офіціанта (`web-pos`), систему знижок, керування столиками, касові зміни (X/Z-звіти), єдину систему бонусів лояльності Urban Club, преміальну темну тему (Dark Mode UI) та безшовний ScrollSpy-каталог.** Бекенд, бот, інфраструктура, каталог закладів,
> мультилокаційний кошик, чекаут (доставка/самовивіз зі збереженими адресами),
> історія замовлень із повтором у клік, інтерактивне керування замовленнями у боті, верифікація номера телефону,
> автономні веб-сайти (`web-pizza`, `web-croissants`, `web-group`) з єдиним графітовим дизайном, верифікованим кабінетом та спільним балансом бонусів,
> POS-портал для офіціантів (`web-pos`) зі столиками, знижками (3%, 5%, 10%, 15%, 30%, 50%), поштучною подачею, дозамовленнями та касовими змінами,
> модульна адмін-панель із бізнес-аналітикою, безпечним видаленням клієнтів і маркетинговими розсилками, захищені Docker-контейнери (non-root user + healthcheck),
> а також Redis-кешування, автоінвалідація через PostgreSQL NOTIFY, Rate Limiting та 178 автотестів (100% green).
> Далі — онлайн-оплата (Фаза 4 / 7), див. [Roadmap](#roadmap).

## Можливості

**Готово:**

- **Реєстрація та профіль клієнта:**
  - Вхід без окремого логіна — особа встановлюється з підписаного Telegram `initData`
  - Перегляд картки клієнта (код `DM-{telegram_id}`, баланс бонусів)
  - Редагування імені, прізвища, основної та додаткової адреси доставки (`/profile`) з безпечною синхронізацією стану (`useEffect`)
  - Верифікація номера телефону через кнопку «Поділитися контактом» у боті з захистом від несанкціонованої зміни
- **Каталог:**
  - Дворівневі категорії обох закладів (Urban Pizza та Urban Bakery)
  - Товари, розкладені по секціях із липкими заголовками
  - Картка товару з вибором розміру, варіантів цін і ваги
  - Опції «на вибір» з безкоштовною квотою (`free_count`): соуси, напої тощо
  - Єдиний модуль розрахунку лімітів і вартості опцій (`@/utils/productOptions.ts`) на фронтенді
  - Стоп-лист (`is_available`): товар або окремий розмір ховається без порушення цілісності БД
- **Кошик:**
  - Додавання з перевіркою мінімальних/максимальних лімітів опцій на сервері
  - Зміна кількості з атомарною ревалідацією опцій (`FOR UPDATE`), видалення, повне очищення
  - Оптимізована пакетна вставка/оновлення опцій (`executemany`) та утилізація з'єднань БД без overhead
  - Мультилокаційний кошик: групування позицій за закладом із підказкою про роздільне оформлення
- **Оформлення замовлення (Checkout):**
  - Вибір типу отримання: 🛵 доставка кур'єром за адресою або 🛍️ самовивіз із закладу
  - Довідник адрес доставки Вишгорода з підтримкою стоп-листа та автокомплітом
  - Вибір запланованого часу (scheduled time) з оптимізованим розрахунком слотів (`useMemo`) та урахуванням робочих годин закладу (мінімум +30 хв)
  - Вибір способу оплати: 💵 готівка або 💳 картка
  - Коментар до замовлення, автозаповнення контактних даних з профілю
  - Окреме оформлення страв для кожного закладу в один клік
  - Екран успішного замовлення з деталями
- **Історія замовлень (Фаза 3):**
  - Перегляд списку минулих замовлень користувача (`/orders`) з оптимізованим композитним індексом `(telegram_id, id DESC)`
  - Деталі замовлення: склад, статус приготування/доставки, фінальна ціна
  - Повтор будь-якого минулого замовлення в кошик в один клік
- **Керування замовленнями через Telegram-бота:**
  - Миттєве надсилання картки нового замовлення персоналу в чат
  - Інтерактивні інлайн-кнопки перемикання статусів (в процесі, готується, готово, на доставці, виконано, скасовано)
  - Кнопки швидкого коригування часу доставки (+15, +30, +45, +1 год, якнайшвидше)
  - Автоматичне сповіщення клієнта у боті про зміну статусу та оновлення часу
  - RBAC-контроль доступу менеджера безпосередньо через таблицю `managers` у БД
- **Автономна веб-панель адміністратора (`web-admin`, порт `5178`):**
  - Окремий сервіс React 19 + Tailwind v4 + Vite (`web-admin/`), оптимізований для персоналу та відокремлений від клієнтського Mini App
  - Авторизація персоналу через Telegram Login Widget та одноразові коди доступу
  - Модульна архітектура бекенду (`api/src/routers/admin/`) та інтерфейсу (`web-admin/src/components/admin/`)
  - Керування меню, категоріями та підкатегоріями (з роздільним редагуванням, автозсувом порядкових номерів та групуванням страв)
  - Керування товарами, варіантами та групами модифікаторів (включно з масовим редагуванням)
  - Керування ролями та персоналом закладів
  - Моніторинг та редагування замовлень зі зміною статусів та позицій, чітка ідентифікація джерела замовлення (`🏛️ Заклад` зі столом/офіціантом, `🥐 Веб-сайт`, `🍕 Веб-сайт`, `🤖 Telegram`)
  - Керування базою користувачів (блокування, нотатки, статус верифікації телефону, безпечне видалення із захистом історії замовлень `ON DELETE SET NULL`)
  - Керування адресним довідником та стоп-листом вулиць
  - Очищення кешу каталогу в один клік
- **Бізнес-аналітика та маркетингові розсилки (Фаза 5):**
  - Дашборд показників: виторг, середній чек, динаміка замовлень за періодами
  - Фільтрація аналітики за закладами, способами доставки та типами оплати
  - Топ найпопулярніших страв за кількістю замовлень та сумою
  - Таргетовані розсилки через Telegram-бота з веб-адмінки
  - Гнучка сегментація аудиторії (всі, активні за 30 днів, сплячі >30 днів, топ-замовники від 5 замовлень)
  - Telegram Live Preview тексту повідомлення з підтримкою форматування та безпечна відправка з дотриманням рейт-лімітів
- **POS-портал для персоналу та офіціантів (`web-pos`):**
  - Авторизація за 4-значним PIN-кодом або вибором офіціанта зі списку
  - Окремі воркфлоу: «В закладі» (вибір столу, відкладена оплата, відправка чека на кухню) та «Takeaway» (миттєва оплата)
  - Гнучка система знижок (3%, 5%, 10%, 15%, 30%, 50%) для столів та замовлень на виніс із чесними правилами взаємодії з кешбеком і балами

  - Динамічне дозамовлення нових позицій до відкритого столу з перерахунком суми
  - Розрахунок столу при закритті (готівка / картка) з пошуком гостя за телефоном та списанням балів Urban Club
  - Повне керування модифікаторами: степери кількості `[ − ] [ + ]`, безкоштовні квоти (`free_count`) та автопідтягування
  - Касові зміни та звітність (X/Z-звіти, внесення/винесення готівки, підрахунок виручки та розбіжностей з Telegram-сповіщеннями)
  - Редагування відкритих чеків (степери зміни кількості, поштучне видалення страв) та повне скасування з обов'язковою причиною та поверненням бонусів
  - Звукові сповіщення кухаря/офіціанта на Web Audio API та періодичний автоапдейт замовлень (10с)
  - Мобільна оптимізація під планшети та смартфони (iOS Safe Area, числова клавіатура)

  - Централізований `BonusService` для розрахунку, списання та нарахування кешбеку
  - Журнал транзакцій `bonus_transactions` та безпечні баланси
  - Спільний доступ до бонусів між веб-сайтами (`web-pizza`, `web-croissants`, `web-group`), ботом, Mini App та POS-порталом

  - Підтримка обходу кешу (`?bypass_cache=true`, `X-Bypass-Cache: true`)
  - Rate Limiting на базі Redis для захисту публічних ендпоінтів від спаму
  - Складені індекси для каталогу й історії замовлень (`idx_orders_telegram_id_id_desc`)
- **Безпека контейнерів та оркестрація (Docker):**
  - Запуск сервісів `api` та `bot` від непривілейованого системного користувача `appuser` (non-root)
  - Вбудований Docker Healthcheck для FastAPI (`/api/health`)
  - Коректна залежність запуску в `docker-compose.yml`: `bot` та `caddy` очікують стану `service_healthy` від `api`
- **Нативне медіа-сховище та двоконтурне автостискання фотографій:**

  - Локальне збереження у томі `uploads_data` (`/app/uploads`) та універсальна роздача з довготривалим кешуванням через Caddy
  - Інтерактивний UI завантаження з прев'ю, зміною чи видаленням фото та швидкою кнопкою 📷 у каталозі
- **Бот:**
  - `/start` із кнопкою запуску Mini App та постійна Menu Button зліва від поля вводу
  - Верифікація контактного номера через відправку контакту
  - Захищений запуск від `appuser`

**Екрани Mini App:** онбординг, категорії, список товарів із секціями, картка товару,
кошик із розділенням закладу, чекаут, екран успішного замовлення, історія замовлень, профіль клієнта,
адмін-панель (замовлення, клієнти, персонал, адреси, аналітика, розсилки), контакти.
Нативна кнопка «Назад», тактильний відгук (Haptic), підтримка світлої й темної тем Telegram з адаптацією під фірмову палітру Urban (Bakery & Pizza) та шрифтами Playfair Display і Plus Jakarta Sans.

**Контроль доступу та безпека:**

- **Клієнтське меню та замовлення:** доступні **виключно** з додатку Telegram (iOS, Android, Desktop) або Telegram Web фрейму.
- **Адмін-панель (`/admin`):** доступна з десктопних браузерів за прямим посиланням (`https://nikiga-ax.duckdns.org/admin`). Будь-які неавторизовані запити до інших сторінок поза Telegram автоматично редиректяться в адмінку, а кнопки «До меню» в адмінці приховуються.
- **Захист API:** ендпоінти каталогу (`/api/categories`, `/api/products`), локацій та доставки захищені залежністю `require_telegram_or_staff` (вимагають підпис `initData` або токен персоналу).

**Заплановано:** Telegram Payments (Фаза 4) — див. [Development.md](Development.md).

## Архітектура

```text
Telegram client
      │
      ├── Bot (aiogram)  ──── polling ────► Telegram Bot API
      │      └── /start, Menu Button, надалі нотифікації
      │
      └── Mini App (WebView)
             │  HTTPS, заголовок X-Telegram-Init-Data
             ▼
          caddy ──── /        ─► статика React (SPA)
            │   └─── /api/    ─► FastAPI
            │                      │
            ▼                      ▼
          Redis                PostgreSQL
```

Окремої авторизації немає: кожен запит несе `initData`, бекенд перевіряє HMAC-підпис
на `BOT_TOKEN` і дістає з нього `telegram_id`.

## Швидкий старт

### Передумови

- Docker і Docker Compose
- PostgreSQL (зовнішній — у compose не піднімається)
- Бот, створений у [@BotFather](https://t.me/BotFather), і його токен
- HTTPS-URL для Mini App — локально зручно через [ngrok](https://ngrok.com/)
  або Cloudflare Tunnel (BotFather не приймає `http://`)

### Налаштування

```bash
git clone https://github.com/Oleksandr-Nikiha/urban_app.git
cd urban_app

cp .env.example .env
$EDITOR .env          # DATABASE_URL, BOT_TOKEN, MINI_APP_URL
```

Застосувати схему й тестові дані:

```bash
# Застосувати всі міграції (db/migrations/):
for f in $(ls db/migrations/*.sql | sort); do psql "$DATABASE_URL" -f "$f"; done

# Наповнити початковий каталог (Urban Pizza та Urban Bakery):
psql "$DATABASE_URL" -f db/seed/seed_catalog.sql
```

### Запуск

```bash
docker compose -f docker-compose.dev.yml up --build
```

Підіймаються `redis`, `api`, `bot` і `frontend`.
API — на `http://localhost:8010` (Swagger на `/docs`), Mini App — на `http://localhost:5173`.

> Порт на хості — **8010**, а не 8000: 8000 часто зайнятий (у автора — portainer).
> Змінюється в `docker-compose.dev.yml` і `VITE_API_BASE_URL`.

`frontend/node_modules` лежить на хості (а не в анонімному томі) — інакше
IDE не бачить типів. Після зміни `package.json` достатньо перезапустити сервіс:

```bash
docker compose -f docker-compose.dev.yml restart frontend
```

### Змінні оточення

Змінна | Обов'язкова | Опис
--- | --- | ---
`APP_DOMAIN` | для проду | Публічний домен для Caddy (автоматичний SSL)
`POSTGRES_DB` | для проду | Назва бази даних PostgreSQL (типово `urban_app_db`)
`POSTGRES_USER` | для проду | Користувач PostgreSQL (типово `urban_user`)
`POSTGRES_PASSWORD` | для проду | Пароль до бази даних PostgreSQL
`DATABASE_URL` | так | DSN PostgreSQL, напр. `postgresql://user:pass@host:5432/urban_app_db`
`BOT_TOKEN` | так | Токен від BotFather; ним же валідується `initData`
`MINI_APP_URL` | так | HTTPS-URL Mini App для кнопки в боті
`MANAGER_CHAT_ID` | ні | ID чату/групи менеджерів у Telegram для отримання карток нових замовлень та модерації
`REDIS_URL` | ні | URL підключення до Redis (типово `redis://redis:6379/0`)
`CATALOG_CACHE_ENABLED` | ні | Увімкнення кешування каталогу в Redis (типово `true`)
`CATALOG_CACHE_TTL` | ні | Час життя кешу публічного каталогу в секундах (типово `1800` = 30 хв)
`RATE_LIMIT_ENABLED` | ні | Захист публічних ендпоінтів від спаму через Redis (типово `true`)
`RATE_LIMIT_REQUESTS` | ні | Ліміт кількості запитів у вікні (типово `120`)
`RATE_LIMIT_WINDOW_SECONDS` | ні | Вікно підрахунку запитів у секундах (типово `60`)
`CORS_ORIGINS` | ні | Origins через кому; типово Vite на `:5173` або прод-домен
`API_DEBUG` | ні | Режим налагодження (типово `false`)
`VITE_API_BASE_URL` | ні | Базовий URL API для фронтенду (типово `/api`)
`VITE_PUBLIC_HOST` | ні | Публічний хост/домен тунелю для `allowedHosts` у Vite dev-сервері
`VITE_DEV_INIT_DATA` | ні | Підписаний тестовий `initData` для розробки у браузері поза Telegram

### 🚀 Розгортання та міграція у Production (Standalone)

Для розгортання застосунку в окремому прод-середовищі (VPS / виділений сервер) реалізовано автономний стек `docker-compose.yml`, який піднімає:

- **`postgres`** (PostgreSQL 16 з persistent томом `postgres_data`)
- **`redis`** (кешування каталогу та rate limiting)
- **`migrator`** (транзакційний автораннер міграцій `schema_migrations`)
- **`api`** (FastAPI від не-root `appuser` з healthcheck)
- **`bot`** (aiogram-бот)
- **`caddy`** (зворотний проксі, роздача React SPA та автоматичний HTTPS/TLS на портах 80 і 443)

#### Швидкий сценарій міграції з dev на новий прод-сервер

1. **Експорт даних з dev-середовища:**

   ```bash
   ./scripts/export_dev_data.sh
   # Створює архів exports/urban_prod_migration_YYYYMMDD_HHMMSS.tar.gz (дамп БД + фотографії)
   ```

2. **Передача на прод-сервер:**

   ```bash
   scp exports/urban_prod_migration_*.tar.gz user@your-prod-server:/home/user/urban_app/
   ```

3. **Ініціалізація та запуск на прод-сервері:**

   ```bash
   cp .env.prod.example .env
   # Заповніть реальні значення APP_DOMAIN, POSTGRES_PASSWORD, BOT_TOKEN, MANAGER_CHAT_ID

   # Імпорт дампу БД та синхронізація медіа-файлів:
   ./scripts/import_prod_data.sh urban_prod_migration_*.tar.gz

   # Призначення вашого акаунта адміністратором (для входу в /admin):
   python3 scripts/create_admin.py <TELEGRAM_ID> "Ім'я"

   # Збірка та запуск прод-стеку:
   ./scripts/deploy_prod.sh
   ```

4. **Автоматичні щоденні бекапи БД (cron):**

   ```bash
   # Додати в crontab (crontab -e):
   0 3 * * * /home/user/urban_app/scripts/backup_prod_db.sh >> /var/log/urban_backup.log 2>&1
   ```

### Тестування API без Telegram

Згенерувати валідний підписаний `initData`:

```bash
python3 scripts/generate_test_init_data.py "$BOT_TOKEN"
```

Рядок діє **24 години**. Коли протухне, фронтенд почне отримувати `401` —
оновити разом із перезапуском контейнера можна одною командою:

```bash
./scripts/refresh_dev_init_data.sh
```

Далі є два шляхи.

**Swagger.** Відкрити `http://localhost:8010/docs` → **Authorize** → вставити рядок.
Він застосується до всіх захищених ендпоінтів одразу.

**curl.** Зручно покласти рядок у змінну — він дійсний 24 години:

```bash
export INIT_DATA=$(python3 scripts/generate_test_init_data.py "$BOT_TOKEN" | tail -2 | head -1)

curl -s -H "X-Telegram-Init-Data: $INIT_DATA" localhost:8010/api/me | jq

curl -s -X POST localhost:8010/api/cart/items \
  -H "X-Telegram-Init-Data: $INIT_DATA" -H 'Content-Type: application/json' \
  -d '{"variant_id":1,"qty":2,"options":[]}' | jq
```

Товар із обовʼязковими опціями без них не додасться — бекенд віддасть `400`
і напише, якої групи бракує:

```bash
curl -s -X POST localhost:8010/api/cart/items \
  -H "X-Telegram-Init-Data: $INIT_DATA" -H 'Content-Type: application/json' \
  -d '{"variant_id":162,"qty":1,"options":[{"group_id":2,"variant_id":194},
                                           {"group_id":3,"variant_id":180}]}' | jq
```

Тестовий користувач — `telegram_id=111111111`, зашитий у самому скрипті.
Підставте туди свій справжній id, якщо хочете бачити себе в БД після `/register`.

Без заголовка або з невалідним підписом захищені ендпоінти віддають `401`.

### Перевірки

Те саме, що ганяє CI:

```bash
docker compose up -d --build
```

Стек: `caddy` (порт 80), `api`, `bot`, `redis`. Фронтенд збирається всередині
образу caddy на етапі build.

За замовчуванням Caddy слухає порт 80 (HTTP) або автоматично керує TLS при
вказанні домену через змінну `APP_DOMAIN` (див. [caddy/Caddyfile](caddy/Caddyfile)).

### Публікація для Telegram

Telegram відкриває Mini App лише за HTTPS-URL. Потрібні домен і сертифікат;
далі reverse-proxy на хості віддає застосунок і API з одного origin:

```caddy
handle /api/* {
    reverse_proxy 127.0.0.1:8010
}
handle {
    root * /var/www/urban-app
    try_files {path} /index.html
    file_server
}
```

Статику можна зібрати локально (`npm --prefix frontend run build`) і розкласти
у директорію веб-сервера (наприклад, `/var/www/urban-app`).

**Dev-сервер Vite назовні виставляти не можна.** Він віддає вихідні тексти
з уже підставленими значеннями `VITE_*`-змінних, а серед них `VITE_DEV_INIT_DATA` —
підписаний `initData`, тобто валідні облікові дані до захищеного API.
Тому в dev-compose порт прив'язаний до `127.0.0.1`.

`X-Frame-Options` не виставляти: Telegram Desktop відкриває Mini App в iframe.

У `.env` вказати `MINI_APP_URL`, `VITE_PUBLIC_HOST` (домен потрібен Vite
для `allowedHosts`) і додати домен у `CORS_ORIGINS`. Після зміни `MINI_APP_URL`
перестворити контейнер бота — він виставляє Menu Button на старті:

```bash
docker compose -f docker-compose.dev.yml up -d --force-recreate bot
```
